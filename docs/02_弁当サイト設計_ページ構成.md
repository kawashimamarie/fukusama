# 02 弁当事業サイト（ebisenka.jp）設計・ページ構成

## 1. サイトの役割
法人の継続的な仕入れ・大口注文の**相談（問い合わせ）を獲得するための営業サイト**。一般消費者向けの単発注文やレストラン集客（ebisenka-honten.jp の役割）とは分けている。

## 2. ページ構成一覧

| URL | ページ | 主な目的 | 主なキーワード |
|---|---|---|---|
| `/` | TOP | 事業内容を一目で伝え、卸ページ・問い合わせへ送る | 弁当 製造 卸／法人向け 弁当 |
| `/wholesale/` | 法人向け弁当卸（最重要） | 法人担当者の疑問（弁当・数量・継続・納品・地域・見積・流れ）に答え、問い合わせへ | 弁当 卸／弁当 仕入れ／法人向け 弁当／弁当 大量注文 |
| `/bento/` | 弁当紹介 | 実際に製造している弁当を示す | 中華弁当 卸 |
| `/kitchen/` | 製造体制・実績 | セントラルキッチン・1,500食以上の実績（注記つき） | 弁当 製造 |
| `/about/` | 会社案内 | 福進発展との関係・会社概要（詳細はコーポレートへ） | 指名検索 |
| `/contact/` | お問い合わせ・お見積もり | 法人向け相談フォーム | — |
| `/contact/thanks/` | 送信完了 | noindex | — |
| `/privacy/` | プライバシーポリシー | フォーム設置に必要 | — |
| `/404.html` | エラーページ | noindex | — |

### TOP の構成（ご指示の7項目に対応）
1. ファーストビュー：見出し「毎日のおいしさを、まとまった数でも。」＋サブコピー＋CTA2つ（法人向け卸販売について／お問い合わせ）。右側に実際の弁当写真と「1,500食以上（製造数が多いときの実績）」「1995年創業」「法人卸」の3項目
2. 特徴（FEATURES）3項目
3. 製造実績（1,500食以上＋注記）
4. 法人向け卸販売（こんなご相談をお待ちしています）
5. 弁当の紹介
6. ご相談から取引開始まで（5ステップ）
7. よくある質問（5問）
8. お問い合わせ（CTA帯）

### 法人向け弁当卸ページの考え方
未確認の条件（地域・価格・最低数・納品方法）を**架空の数字で埋めず**、「ご相談時に確認する項目」として見せ、フォームに書いてほしい情報（数量・地域・時期・利用形態・予算）を一覧にしている。法人担当者が「何を伝えれば話が進むか」が分かるため、条件未確定のままでも問い合わせにつながる。条件が確定したら同じ枠に事実を書き足せる。

### フォーム項目
会社名＊／担当者名＊／メール＊／電話／お問い合わせ種別＊（継続的な卸取引・仕入れ／大口注文／弁当販売の新規事業／その他）／希望数量／希望納品地域／希望開始時期／お問い合わせ内容＊／プライバシーポリシー同意＊（＊＝必須）
- 数量・地域は**自由記述**（選択肢にすると対応範囲を保証しているように見えるため）
- 必須は最低限にし、未定の項目は空欄でよいと明記

## 3. 導線
- 全ページのヘッダー右に「お問い合わせ・お見積もり」
- スマートフォンはヒーローを過ぎると画面下に「卸・大口注文のご相談」ボタンが出る（問い合わせページでは出さない）
- 各ページ末尾に問い合わせCTA帯
- コーポレートサイト → ebisenka.jp：事業紹介カード・事業サイトカード・business.html・restaurant.html の「弁当事業の詳細を見る」
- ebisenka.jp → コーポレート：会社案内・フッター。レストラン（ebisenka-honten.jp）は「店舗サイト」と明記して区別

## 4. デザインコンセプト「仕切り」
弁当の**仕切り**をレイアウトの骨格にした。黒い弁当容器＝濃色パネル（tray）、ご飯＝生成りの背景、海老専家の朱＝アクセント。

| 要素 | 内容 |
|---|---|
| 色 | 生成り `#fbf7f1`／米色 `#f3ece1`／墨 `#1d1916`／海老専家の朱 `#b71c2b`（白文字でコントラスト比 AA を満たす濃さ）／海老色 `#f08a6c`（濃色背景上のみ） |
| 書体 | 見出し：しっぽり明朝 B1（Google Fonts、非同期読み込み）／本文：端末の標準ゴシック（表示速度優先） |
| 象徴的な表現 | ヒーローの「弁当容器」グリッド（写真＋実績3マス）、下層ページ見出し横の小さな仕切り図、CTA帯の仕切り線画、製造の流れ図 |
| 動き | 表示時のフェードアップ（1回のみ）、写真のごく弱いパララックス（対応ブラウザのみ、CSSのみ）。ローディング画面なし。「視差効果を減らす」設定の端末では動きを止める |
| ロゴ | コーポレートサイトにある「海老専家」筆文字ロゴを透過加工して使用 |

## 5. 技術構成
- 静的HTML＋CSS＋少量のJS（外部ライブラリなし）。フォーム送信のみPHP（`contact/send.php`）
- `build.py`（Python標準ライブラリのみ）で共通ヘッダー・フッター・メタ情報・構造化データ・sitemap.xml を生成し、`dist/` に出力
- コーポレートサイトとはファイル・アセット・公開先を完全に分離（`corporate/` と `bento-site/`）

## 6. 将来のEC追加を見据えた点
現時点ではEC機能・外部サービスは入れていない。追加しやすいように以下を用意した。
- URL：`/bento/`（商品一覧）の下に `/bento/<商品ID>/`（商品詳細）を置ける。`/shop/` `/cart/` `/order/` `/account/`（注文履歴）は未使用で予約
- 「内容／価格／ご注文条件」の定義リストを商品詳細の型として流用できる
- 共通レイアウトとページ生成が分離しているため、ECを外部サービス（Shopify等）や別システムで作る場合も、ヘッダー・フッター・デザイントークン（CSS変数）を移植しやすい
- 法人向け注文（掛け払い・定期発注）は一般ECと要件が大きく異なるため、導入時に「一般向けEC」と「法人の発注フォーム」を分けるかを決めるのがよい
