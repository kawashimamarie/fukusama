# 13 プレビュー：アップロード手順と即時停止手順

対象：`https://ebisenka.jp/_preview-fk2026/`（設計は `12_パスワード付きプレビュー環境_設計.md`）
**サーバーへの書き込みは、ご承認後に実施します。** ★ が書き込み操作です。

---

## 1. アップロードするファイル

| ファイル | 内容 | 置き場所 |
|---|---|---|
| `preview-package/_preview-fk2026-panel.zip` の中身（`_preview-fk2026/` フォルダ・77ファイル・約12MB） | 入口ページ、弁当サイト（`bento/`）、コーポレート修正版（`corporate/`）。`.htaccess` は含まない | ebisenka.jp の公開フォルダ直下に `_preview-fk2026/` として |

これ以外のファイルはアップロードしない（ebisenka.jp 直下、fukushin-e.co.jp には何も置かない）。
zip はリポジトリで `python3 preview/build_package.py` を実行すると作られる（Git には含まれない）。作成時に公開中コーポレートとの差分確認と、`.htaccess` が混ざっていないかの検査が自動で行われる。

## 2. 作業前の確認（書き込みなし）
1. お名前.com から「2026/10/21 サーバーメンテナンス」の対象案内メールが来ていないか確認する
   - 対象なら 10/21 当日は作業しない。10/22 以降に作業する場合は、コントロールパネルで**新しいホスト名**を確認し、FTP ソフトの接続先を直してから作業する（古いホスト名で行った更新は新サーバーに反映されない）
2. `python3 preview/check_live.py` → 「公開中データは取り込み時点から変わっていません」
3. コントロールパネルのファイルマネージャーで、ebisenka.jp の公開フォルダが空であること、`_preview-fk2026` が無いことを確認
4. ID とパスワードを決める（パスワードは推測されにくい12文字以上。メール・チャット・資料に書かない）

## 3. 手動作業手順（推奨：コントロールパネルの「アクセス制限」）

**順番が重要：空のフォルダに先に鍵を掛け、鍵を確認してから中身を入れる。**（中身が鍵なしで見える時間をつくらない）

| 手順 | 操作 | 書き込み |
|---|---|---|
| 1 | ファイルマネージャーで、ebisenka.jp の公開フォルダ直下に空のフォルダ `_preview-fk2026` を作る | ★ |
| 2 | コントロールパネル「セキュリティ」→「アクセス制限」→ 選択中のドメインを ebisenka.jp に切り替え →「制限中のフォルダ」→「＋制限するフォルダを追加」→ フォルダ `_preview-fk2026`、ユーザー名・パスワードを入力 →「確認する」→ 登録 | ★ |
| 3 | 鍵の確認：シークレットウィンドウで `https://ebisenka.jp/_preview-fk2026/` を開き、**ID・パスワードの入力画面が出ること**を確認（または `python3 preview/check_preview.py https://ebisenka.jp/_preview-fk2026/`）。入力画面が出なければここで中止し、手順1のフォルダを削除 | なし |
| 4 | `_preview-fk2026-panel.zip` を展開し、**`_preview-fk2026` フォルダの中身**（`index.html`・`bento/`・`corporate/`）を、サーバーの `_preview-fk2026` フォルダの中にアップロード（FTP ソフト、またはファイルマネージャー） | ★ |
| 5 | もう一度 `python3 preview/check_preview.py https://ebisenka.jp/_preview-fk2026/` → 【OK】であること。【NG】なら直ちに「5. 即時停止」 | なし |
| 6 | ID・パスワードを入力して表示確認（下記チェック） | なし |
| 7 | 担当者に URL を共有。ID・パスワードは電話など別の経路で伝える | なし |

※ ファイルマネージャーで zip を直接展開できるかは未確認。できない場合は、手元で展開してからフォルダごとアップロードする。
※ アップロードの際、`_preview-fk2026` の中に `.htaccess` を作らない・置かない（置くとコントロールパネルの鍵が無効になるおそれがある）。

### 表示確認チェック（手順6）
- [ ] パスワード無し（シークレットウィンドウ）→ 入力画面が出る
- [ ] 正しい ID・パスワード → 入口ページ → 弁当サイト・コーポレートが開く
- [ ] `https://ebisenka.jp/` → 今までどおり 403（変化なし）
- [ ] `https://fukushin-e.co.jp/` → 今までどおり表示（変化なし）
- [ ] 弁当フォームを架空の内容で送信 →「テスト送信を受け付けました／メールは送信していません」、メールが届かない
- [ ] コーポレートのフォームを架空の内容で送信 →「メールは送信していません」
- [ ] スマートフォンでも、ID・パスワード入力後に表示される

テスト入力の例：会社名「テスト株式会社」／担当者名「テスト 太郎」／メール「test@example.com」／電話番号は空欄／内容「テスト送信」。実在の個人情報は入力しない。

### 代替：.htaccess＋.htpasswd 方式（コントロールパネルの制限が使えない場合のみ）
1. 公開フォルダの外のフルパスを確認し、手元で `.htpasswd_preview` を作成（例：`htpasswd -cB .htpasswd_preview ユーザー名`）
2. `python3 preview/build_package.py --auth htaccess --htpasswd-path <フルパス>` で `_preview-fk2026-htaccess.zip` を作り直す
3. ★ `.htpasswd_preview` を公開フォルダの外へ → ★ 空の `_preview-fk2026` に `.htaccess` だけを先に置く → 鍵を確認 → ★ 残りをアップロード
4. コントロールパネルの「アクセス制限」と同じフォルダで併用しない

## 4. 公開後の確認と削除

### 確認期間中
- 共有後もときどき `python3 preview/check_preview.py https://ebisenka.jp/_preview-fk2026/` を実行し、【OK】を確認する（サーバー側の変更やメンテナンスの後は必ず）

### 削除（確認期間終了時・本番公開時）
1. ★ ファイルマネージャーで `_preview-fk2026` フォルダを**フォルダごと**削除
2. ★ コントロールパネル「アクセス制限」から `_preview-fk2026` の設定を削除（代替方式の場合は公開フォルダ外の `.htpasswd_preview` を削除）
3. `https://ebisenka.jp/_preview-fk2026/` が 404 になることを確認
4. 担当者にプレビュー終了を連絡

---

## 5. 認証が効かないときの即時停止手順

**こんなときに実行**：パスワード入力画面が出ずに中身が見えた／`check_preview.py` が【NG】を出した／ID・パスワードが社外に漏れた疑いがある。

### いちばん早い停止（1〜2分）
1. ★ コントロールパネルのファイルマネージャー（または FTP ソフト）で、`_preview-fk2026` フォルダの**名前を変更**する
   - 例：`_preview-fk2026` → `_off-` に任意の英数字を続けた推測されにくい名前（例 `_off-k39w7q`）
   - 名前を変えた瞬間に、元の URL では見られなくなる（404）。中身を削除しないので原因調査にも使える
2. シークレットウィンドウで `https://ebisenka.jp/_preview-fk2026/` を開き、**404（見つかりません）**になることを確認
   （または `python3 preview/check_preview.py https://ebisenka.jp/_preview-fk2026/` →「存在しない」）
3. 調査が不要なら、そのまま名前を変えたフォルダを削除する

### フォルダ操作ができない場合
- ★ ファイルマネージャーで `_preview-fk2026` フォルダごと削除する（元データは手元の zip にあるので、削除しても再構築できる）
- どちらもできない場合（メンテナンス中など）は、お名前.com のサポートに連絡する

### 停止後にやること
| # | 内容 |
|---|---|
| 1 | パスワードが漏れた疑いがある場合は、コントロールパネル「アクセス制限」でパスワードを初期化（または設定を削除） |
| 2 | 鍵が効かなかった原因を確認（よくある原因：フォルダ内に `.htaccess` が置かれていた／制限を別のフォルダに設定していた／ドメインの選択違い） |
| 3 | 公開されていた時間が長い場合は、検索エンジンに登録されていないか確認（`site:ebisenka.jp/_preview-fk2026` で検索）。全ページに noindex を入れているため、通常は登録されない |
| 4 | 原因を直してから「3. 手動作業手順」を最初からやり直す |

※ 停止作業ではプレビューのフォルダ以外（ebisenka.jp 直下、fukushin-e.co.jp、DNS・SSL・メール）には触れない。
