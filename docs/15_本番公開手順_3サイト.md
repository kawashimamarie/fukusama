# 15 本番公開手順（3サイト）

> **2026-10-12 更新：公開は GitHub Actions による自動公開の仕組み（`17_自動公開システム.md`）で行う予定。** この手順（ZIP とファイルマネージャーによる手作業）は、自動公開が使えない場合の予備として残す。


**この手順は、ご依頼者様の最終承認後に、お客様がお名前.com の管理画面で実施します。承認前は一切実施しません。**
（2026-10-10 最終版。パスワード付きプレビュー環境は使わない）

## 現在の状態（2026-10-10 更新）
- **公開準備済み・公開は保留中。** 別案件（Nexus サイト）での「Claude からお名前.com への FTP アップロード」の検証結果が出るまで、3サイトとも公開・アップロードを開始しない
- FTP が使えると確認できた場合は、Claude 側からアップロードする方式に切り替える予定（`16_FTPアップロード方式への切り替え準備.md`）。その場合も、**ご依頼者様が明示的に公開を承認するまでは本番サーバーに書き込まない**
- 福記美食：WordPress の維持は必須ではない（静的サイトへの切り替えで可）。ただし既存サイトのバックアップと復元手段は必ず確保する。下記の「WordPress を残したまま切り替える」方法は、復元が最も速いため引き続きこの方法で行う（WordPress の削除は、公開後に落ち着いてから別途判断）
- フォームの実送信テストは公開後に行う。**テストが終わるまで、本番での実際のメール受信は未確認**

## 進め方の約束
- 順番：**① ebisenka.jp → ② ebisenka-seavans.com（福記美食）→ ③ fukushin-e.co.jp（コーポレート）**

- サーバー・管理画面の操作はお客様が行う。こちらはファイルの準備・確認、手順のご案内、外部からの表示確認を行う

## 2. 事前確認（すべて読むだけ。書き込みなし）
- [ ] お名前.com の「2026/10/21 サーバーメンテナンス」の対象案内メールが来ていないか。対象なら **10/21 当日は作業しない**。メンテナンス後は旧サーバーへの更新が新サーバーに反映されないため、10/22 以降に FTP ソフトを使う場合は新しいホスト名に直す（ファイルマネージャーなら影響なし）
- [ ] コントロールパネル「サーバー」→「自動バックアップ」で、**前日分のバックアップ**（Web・メール・データベース、1日1回・14日分）があること（[公式ガイド](https://www.onamae-server.com/guide/rs/p/62)）
- [ ] `python3 preview/check_live.py` で、公開中のコーポレートが取り込み時点から変わっていないこと（変わっていれば作業を止めて連絡）
- [ ] ファイルマネージャーで `public_html` の中のフォルダ名を確認（スクリーンショットを共有）
- [ ] 福記美食フォルダの `.htaccess` の**中身を表示して**共有（編集・保存はしない）。キャッシュ系プラグイン（WP Super Cache、W3 Total Cache など）の設定が書かれていないかを確認する（公開ページの HTML からは、WordPress 7.1.3・All in One SEO・Site Kit のみ確認でき、キャッシュ系プラグインの痕跡は無かった）
- [ ] コントロールパネルの「サーバーキャッシュ」設定画面を開き、各ドメインのキャッシュの状態を確認（設定は変えない）。**3ドメインとも配信時に `x-nginx-cache` が付いており、サーバーキャッシュが有効**。更新後に古い表示が残ることがあるため、各サイトの作業の最後に「キャッシュの削除」を行う（公式ガイド「[サーバーキャッシュを設定する](https://www.onamae-server.com/guide/rs/p/58)」：任意のタイミングで削除できる）

## 4. ② 福記美食（ebisenka-seavans.com）の切り替え（WordPress は削除・変更しない）
| 確認項目 | 内容 |
|---|---|
| 対象ファイル | `2_ebisenka-seavans.com_<日時>.zip` の中身（31ファイル）＋ `.htaccess` への追記 |
| 置き場所 | `public_html/ebisenka-seavans.com/`（WordPress と同じフォルダ） |
| バックアップ | 自動バックアップ（前日分）の確認＋**既存 `.htaccess` のダウンロード**＋可能ならフォルダ全体のダウンロード（`fukuki-site/live-backup-20261010/` に公開ページの HTML・画像の控えあり） |
| 変更内容 | ファイルの**追加**と `.htaccess` 先頭への**追記**のみ。WordPress のファイル・データベース・`wp-content/uploads` には触れない |
| 元に戻す方法 | `index.html` を削除 → 元の `.htaccess` に戻す → サーバーキャッシュ削除（1〜2分） |

### 考え方
WordPress の転送設定は「実在するファイル・フォルダはそのまま表示する」作りのため、追加したページが優先して表示される。トップページは `.htaccess` の追記で `index.html` を優先させる。元に戻すときは追加分を外すだけ。
（ローカルの Apache で、WordPress と同じ転送設定を使って、切り替え・旧URL転送11件・管理画面が残ること・元に戻す動作を検証済み）

### 手順
| 手順 | 操作 | この時点の表示 |
|---|---|---|
| 1 | フォルダ内に、新しいページと同じ名前（`bento` `kitchen` `wholesale` `access` `contact` `assets` `index.html` `404.html` `robots.txt` `sitemap.xml`）のファイル・フォルダが**既に無いこと**を確認。あれば作業を止めて連絡 | 旧サイト |
| 2 | ★ 既存の `.htaccess` をダウンロードして保管 | 旧サイト |
| 3 | ★ zip の中身のうち **`index.html` 以外**をすべてアップロード | トップは旧サイトのまま。`/bento/` などの新しいURLは新ページ |
| 4 | ★ 既存の `.htaccess` の**先頭**（`# BEGIN WordPress` より上）に追記ファイルの内容を貼り付けて保存 | トップは旧サイトのまま。旧URL（/party/ など）の転送が始まる |
| 5 | ★ **`index.html` をアップロード** | **ここでトップが新しいデザインに切り替わる** |
| 6 | ★ サーバーキャッシュを削除（ebisenka-seavans.com） | 古いトップが残っていれば消える |

### 切り替え後の確認
- [ ] https://ebisenka-seavans.com/ が新しいトップ（「毎日のお弁当を、この厨房から。」の下に「お弁当は、店頭でお買い求めいただけます。」）
- [ ] /bento/ /kitchen/ /wholesale/ /access/ /contact/ が表示される
- [ ] 旧URL：/lunch/ /food/ → /bento/、/commitment/ → /kitchen/、/info/ → /access/、/party/ /drink/ /campaign/ /news/ /sitemap/ /privacy/ → トップ
- [ ] WordPress の管理画面（/wp-admin/）にログインできる
- [ ] 画像（/wp-content/uploads/ 以下）が今までどおり開ける
- [ ] スマートフォンで表示（下部に「お弁当の店頭販売」「店舗に電話」のボタン）

### 既知の事項
- `sitemap.xml`・`robots.txt` は、All in One SEO が自動で出していたものに代わって、新しいファイルが表示される（意図どおり）
- 新ページに無い URL（例：古い投稿）は、引き続き WordPress が表示する（旧デザイン）
- Google ビジネスプロフィールは変更しない
