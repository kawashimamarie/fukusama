## 2. 2026-10-21 メンテナンスの正確な影響（公式告知より）

出典：[［レンタルサーバー RSプラン］サーバーメンテナンス（2026/10/21）](https://www.onamae.com/news/article/11565)（掲載開始 2026/10/07）

| 項目 | 公式告知の内容 |
|---|---|
| 日時 | 2026/10/21 00:00 〜 23:59 |
| 対象 | レンタルサーバー RSプランの**一部**のお客様。**対象者には別途メールで案内** |
| メンテナンス中の影響 | ホームページが表示できない／FTP・SSH 接続できない／ファイルマネージャーが使えない／コントロールパネルの一部項目がエラーになる場合がある |
| IPアドレス・ホスト名 | 変更される。メンテナンス前のIPアドレスはメンテナンス後に使えなくなる |
| IPアドレス変更への対応 | ネームサーバーが ns-rs1/ns-rs2.gmoserver.jp のドメインは**対応不要**（本件の ebisenka.jp・fukushin-e.co.jp は該当） |
| ホスト名変更への対応 | FTP ソフト・SSH・独自プログラムの接続先設定を修正する。**変更前のホスト名はメンテナンス後も一時的に使えるが、いずれ使えなくなる** |
| **更新が引き継がれない条件** | 「**本メンテナンス終了後に、変更前の収容ホストで**更新を行われたファイルは、更新内容が変更後の収容ホストに引き継がれません」 |

### 正しい理解（前回の記載を訂正）
- 前回の資料で「移設前に置いたファイルは引き継がれない」と書いたのは**誤り**でした。
- 引き継がれないのは、**メンテナンスが終わった後に、古いホスト（変更前のホスト名）に接続して行った更新**です。メンテナンス後も古いホスト名が一時的につながるため、FTP ソフトの接続先を直さずにアップロードすると、新しいサーバーに反映されません。
- メンテナンス前に置いたファイルの扱いは告知に明記されていませんが、告知の内容（更新を「メンテナンス後の旧ホスト」に限って注意している）から、移設先に移されるものと読めます。念のため、対象だった場合はメンテナンス後に表示を確認します。

### 本件での運用ルール
| 時期 | ルール |
|---|---|
| 対象かどうか不明な間 | お名前.com からの案内メールの有無を確認する |
| 10/21 当日 | 対象の場合、アップロード・削除・設定変更をしない（接続もできない） |
| 10/22 以降（対象の場合） | コントロールパネルで**新しいホスト名**を確認し、FTP ソフトの接続先を更新してから作業する。古いホスト名では作業しない。ファイルマネージャー（ブラウザ）で作業する場合はこの問題は起きにくい |
| 10/21 より前に構築する場合 | 可能。対象なら 10/22 以降にプレビューが表示されること・鍵が掛かっていることを再確認する |
| IP変更後 | 本件の SPF は `include:_spf.onamae.ne.jp` で、お名前.com 側の範囲指定に依存する。メール送信テストは IP 変更後に行う |

## 3. Basic認証（鍵）の公式仕様の再確認

ローカルの Apache での成功は「書き方が正しいこと」の確認にすぎず、お名前.com 上での動作を保証するものではない。公式情報で確認できた範囲は次のとおり。

| 確認項目 | 公式情報 | 出典 |
|---|---|---|
| ID・パスワードによるアクセス制限（RSプラン） | コントロールパネル「セキュリティ」→「アクセス制限」→ ドメインを選択 →「制限中のフォルダ」→「＋制限するフォルダを追加」→ フォルダ・ユーザー名・パスワードを入力。ユーザーは後から追加可 | [サイトにパスワード認証を設定する（RS ご利用ガイド）](https://www.onamae-server.com/guide/rs/p/76) |
| パスワードの確認 | 設定後にパスワードを画面で確認することはできず、忘れた場合は「初期化」（ランダムな文字列になる）| [アクセス制限のユーザー名とパスワード確認方法](https://www.onamae-server.com/guide/rs/p/120) |
| 自作 .htaccess の利用（RSプラン） | 利用できる。ただし次の記述は使えない：`Options Includes`／`Options +FollowSymLinks`／`ErrorDocument 400`／`AuthType Digest`／`MultiViews` | [自分で用意した.htaccessファイルは使用できますか？（ベーシック/RSプラン）](https://help.onamae.com/answer/20820) |
| コントロールパネルの .htaccess 編集機能 | ドメイン直下の .htaccess のみ編集可。下の階層の .htaccess は FTP・ファイルマネージャーで設置 | 同上 |
| **.htaccess とコントロールパネルの制限の関係** | .htaccess を置くと、**そのフォルダ以下ではコントロールパネルで設定した「アクセス制限」などが無効になる**（共用サーバーSDの公式ヘルプに明記。RSプランについては公式ページ本文では確認できていないため、同じ仕様とみなして安全側で設計する） | [.htaccessを使ってアクセス制御はできますか？（共用サーバーSD）](https://help.onamae.com/answer/14053) |
| SSL 申し込み時 | アクセス制限・転送設定は一時解除が必要と案内あり（.htaccess による Basic認証も対象） | [SSLの申し込みができない、利用できない](https://help.onamae.com/answer/20310) |

※公式ページはいずれも自動取得が遮断されているため、内容は公式サイトの検索結果の要約から確認した。**作業当日にコントロールパネルの実画面で手順を確認すること。**

### 確認できなかったこと（＝本番で試すまで分からない）
- `Header`（X-Robots-Tag などの応答ヘッダー）が .htaccess で使えるか（使えないとは書かれていないが、使えるとの記載も見つけられなかった）
- Apache のバージョン（2.2 系か 2.4 系か）→ 代替案の .htaccess は両方で動く書き方にしてある
- コントロールパネルの「アクセス制限」が、内部で `.htaccess` をどこに作るか

### 方式の決定
| | A：コントロールパネル「アクセス制限」（**推奨**） | B：.htaccess＋.htpasswd（代替） |
|---|---|---|
| 公式の手順 | あり（RS ご利用ガイド） | .htaccess は利用可だが、記述方法の個別サポートは期待できない |
| パスワードファイルの置き場所 | 不要（コントロールパネルが管理） | 公開フォルダの外のフルパスを調べる必要あり |
| 失敗の起こりやすさ | 低い | パスの書き間違いで 500 や 401 になりやすい |
| 注意点 | **プレビューフォルダ内のどこにも .htaccess を置かない**（置くとその下の制限が無効になるため）。パッケージ作成時に自動で検査済み | コントロールパネルの制限と併用しない |
| noindex | 全ページのメタタグ＋鍵（401）で対応 | メタタグ＋鍵＋応答ヘッダー（使える場合） |

→ **A を採用**。A がうまくいかない場合のみ B に切り替える（B のパッケージも用意済み）。
